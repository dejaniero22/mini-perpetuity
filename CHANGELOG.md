# Changelog

Format: [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). One entry per plan step.

## [Unreleased]

### Added
- M0: repository foundations: README, governance subset with deviation list, `CLAUDE.md`, `SECURITY.md`, `.claude` settings and `protect-paths` hook with tests, ADR-M0 (governance subset) and ADR-M1 (N named instances, INV-5 deviation), verification backlog, CI with hook tests and gitleaks (actions pinned by SHA), Learning Note.
- M1: `uv` project, `mp` CLI (`status`, `admin init-instance`), config loader, per-instance database and role creation with `PUBLIC` privileges revoked, isolation tests on real PostgreSQL, CI PostgreSQL 18 service container (digest-pinned), Learning Note.
- M2: append-only `events` ledger per instance (app role `SELECT`/`INSERT` only, statement-level trigger blocking `UPDATE`/`DELETE`/`TRUNCATE`), `instance` stamped and checked on every event, `mp admin migrate` for existing instances, ledger tests, Learning Note.
- M3: bi-temporal `memory_objects` with provenance and epistemic types, enforced append-only (column-level grants plus guard trigger; corrections are new versions), `as_of` two-timeline query, `mp add`, ingest seatbelt, ledger events for add/correct, ADR-M3 (secret storage: `0600` file), Learning Note.
- M4: full-text search over approved, currently valid memory (`search_memory`, `mp search`), default-deny `authorize()` (owner-only, allow-list), every search and every denial written to the ledger, query validation and seatbelt, terminal-escape sanitizing on output, migration 0004 (search index; only approved versions may be superseded), Learning Note.
- M5: read-only MCP server over stdio (`mp serve --client NAME --config FILE`, tools `search_memory` and `get_memory`, official `mcp` SDK pinned at 2.3.0), per-client principals registered in the instance config, sensitive objects never returned to clients, results wrapped as untrusted data (random-nonce boundary, escaped content, truncation), rate limits counted from the ledger (60 requests/min per client, 20 recorded denials/min per instance), `get_memory` in the retrieval layer, migration 0005 (event indexes), ADR-M5, Learning Note.
- M6: write-back with quarantine: MCP tool `propose_memory` (always a `proposed` `ai_inference` or `summary`, source pointer required, 2,000-character cap, at most 50 pending per client), owner-only `mp review`, `mp approve` and `mp reject --reason` recording a `human_decision` ledger event, database guards (an AI-attributed row must be a proposal; only two status changes allowed), proposals count toward the request quota, ADR-M6, Learning Note.
- M6b: stronger approval: a separate database role per instance (`mp_<name>_approver`, password typed and stored nowhere, hashed client-side) is the only role that can make memory trusted, change a status, or write `human_decision`/`memory.correct` events; the everyday role can only create pending memory. `mp add` now stores a pending note (no password), `mp approve`/`mp reject` take several ids or `--all` with one password prompt and one transaction, `mp admin set-approver`, `mp status` shows the approver state, migration 0007, ADR-M6b, Learning Note.
- ADR-M8 (proposed): a local HTTPS web front end: verified research findings, ASVS 5.0.0 Level 2 and WCAG 2.2 AA targets, stack (Starlette, Jinja2, vendored htmx, plain CSS), request-protection design, approval design (typed password, conditional passkey), open spikes MB16 to MB21. Docs only; nothing built.
- M7: `mp doctor` (health checks returned as data for the future UI), `mp backup` (`pg_dump` encrypted with age to public keys in the config, written privately and never overwritten), `mp verify-backup`, `mp admin backup-setup` (key kept outside the config and backup folder), `mp admin restore` (fresh same-name instance, one transaction), migration 0008 (everyday role may read sequences so `pg_dump` works; `instance_name()` search path pinned for restores), CI step installing PostgreSQL 18 client tools and `age`, ADR-M7, real-use checklist, Learning Note.
- M8 spikes: `spikes/m8_spike_server.py` (one local HTTPS test page for MB16 passkey PRF, MB17 certificate trust, MB19 `*.localhost`: name-constrained throwaway CA whose key is deleted after signing, loopback-only TLS 1.3 server, strict CSP, nothing stored or sent) and `spikes/mb18_roles.py` (least-privilege setup and read-only roles against a real PostgreSQL); tests for both; `cryptography` pinned as a dev dependency (already in the lock file); `docs/spikes/M8-spikes.md` with results and the Mac steps; Learning Note. No product code changed.
- M8 spike results: verified on Rio's Mac in Chrome 157 (MB17 certificate trust, MB19 `*.localhost` and cookie separation); passkey/PRF dropped by decision (password only, accessibility), so MB16 is withdrawn and the passkey part of the test page removed; ADR-M8 decision 7 amended; Windows support recorded as an open decision (MB24).
- Install guide: `docs/install.md` for PostgreSQL 18 on Mac (Postgres.app) and Windows (EDB installer), written from the official pages with [V]/[U] labels, security note on Postgres.app's no-password default, Windows marked as not yet supported by the code; README quick start links it; backlog MB1 updated, MB25 added. Docs only.
