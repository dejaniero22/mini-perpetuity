# Learning Note: M5

- **The SDK moved on.** The `mcp` package is at 2.3.0 and its server API is `MCPServer` (not the `FastMCP` of 1.x). Everything here was read from the repository at tag `v2.3.0` and the installed source, not from memory. Facts and risks: [ADR-M5](../decisions/ADR-M5-mcp-server.md).
- **Principals.** `authorize` now knows two kinds: the owner and clients registered in the instance config. Each has an allow-list (`search`, `get`); everything else is denied. M6 will add `propose` for clients only.
- **Sensitivity lives in the retrieval layer** (`_SENSITIVE_OK` in `search.py`), keyed on "is this principal the owner". A client cannot reach a sensitive object by any route; a hidden object looks exactly like a missing one (same error text, and the audit event records `found: false`).
- **Rate limits come from the ledger.** `access.gate` counts recent events (`events_time_idx` and `events_actor_time_idx`, migration 0005). Over-quota requests and over-cap denials write nothing, which is what keeps a misbehaving client from flooding an append-only table. Counting then inserting is not atomic, so a burst can overshoot slightly.
- **Output as untrusted data.** A fixed notice, then JSON between a boundary tag with a random nonce; `<`, `>` and `&` are escaped inside the JSON, so stored text can neither forge nor close the boundary. This reduces, but cannot eliminate, the chance a model follows instructions stored in memory: it is a mitigation. **[Inference]** The prompt-injection test proves the server's own behavior does not change and the markup cannot be forged; it cannot prove what a given model does with the text.
- **Errors.** Anticipated failures are `ToolError`s with short messages (the SDK shows those to the model); unexpected exceptions become a generic error and a stderr traceback. Never print to stdout in the server: it carries the protocol.
- **Audit gotcha found while designing `get_memory`.** A call inside `with connection:` rolls back on an exception, which would silently drop the "not found" audit event. `get_memory` therefore returns `None` for a miss and the server raises the error after the connection has committed.
- **A mistake I made and removed.** My first server renamed tools by editing the SDK's private tool table. The decorator already accepts `name=`, which is what it uses now.
- **Registration was tested the way a host would run it** (absolute `mp` path, `serve --client --config`, no environment variables) with the SDK's own client; the real apps were not tested (backlog MB13).
- **The limit that matters most:** a client with shell access as your OS user can read the `0600` password file and talk to PostgreSQL directly, bypassing the server (ADR-M5). Registration constrains what a client can do *through* the server.
- **Verified.** 229 tests (M1 to M5) pass on a local PostgreSQL 18.7 source build, plus Ruff, mypy `--strict`, pip-audit and gitleaks. Nine deliberate weakenings (any client allowed, client may propose, no quota, no denial cap, no sensitive filter, no escaping, constant nonce, no truncation, no startup registration check) each made tests fail, then were reverted. The contract tests run the real server over stdio with the SDK's client; they take about 1 to 3 seconds each.
- **For M6.** `propose_memory` becomes the first client write path, and the first place a client's text enters memory: it must be quarantined as `proposed` (never `approved`), carry the client as agent, pass the seatbelt, and be rate-limited like reads.
