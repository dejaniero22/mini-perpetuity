# Learning Note: M4

- **What comes back (INV-6).** A normal search returns only versions that are `approved`, valid now (`valid_at <= now < invalid_at`) and still current (`expired_at IS NULL`). `--history` returns every version that was ever approved, ignoring the time windows. Proposed and rejected objects are never returned, in either mode. The filter is in the SQL `WHERE`, so nothing unapproved leaves the database.
- **Closing a leak in history mode.** `status = 'superseded'` loses what the version was before. If a never-approved version could be superseded, history would surface unapproved text. Migration 0004 tightens the guard trigger: only an *approved* version may be superseded (so "superseded" implies "was approved"), and `correct_object` refuses non-approved objects with a clear error. Tested at both levels.
- **A gap the mutation check found.** Removing the `expired_at IS NULL` filter changed no test result, because every test row that was expired was also `superseded`, which the approved check already excludes. The clause is defense in depth against an approved row carrying an expiry (the admin role can create one), so it stays, and a test now covers exactly that row.
- **Malformed input and injection.** The query is always a bound parameter, never part of the SQL text. `websearch_to_tsquery` accepts any text without syntax errors, so odd input (`'; DROP TABLE ...`, unbalanced quotes, `%s`, emoji, lone operators) is simply data. Empty, over-500-character and NUL-containing queries and limits outside 1 to 50 are refused with a clear error and not audited. A stop-word-only query returns no results, not an error.
- **Permanent ledger vs queries.** The audit event stores the query text verbatim, in a ledger nothing can edit. So queries go through the ingest seatbelt first: a secret-shaped query is refused *before* anything is written. Non-secret but sensitive text in a query is still kept forever. **[Inference]**
- **Authorization (INV-5, replaced).** `authorize(cfg, Request(principal, instance, action))` is default-deny. It allows a request only if it names this instance, an action on the allow-list (`{"search"}`), and the instance **owner**, defined as `human:<OS user that owns the 0600 config file>`. Every denial is written to the ledger and committed before the error is raised (the one place library code commits, so the refusal survives the caller's rollback). Denial happens before query validation, so a stranger learns nothing about the query rules.
- **Terminal safety.** Stored text is untrusted. `mp search` replaces control characters, including ESC, BEL and the C1 range (for example `0x9b`, a one-byte escape introducer), with `?` before printing.
- **Limits.**
  - Whole-word matching, no prefix search: `postgres` does not match `PostgreSQL` (found by running the README example, which first returned 0 results). Prefix matching (`postgres:*`) would need the stricter `to_tsquery` syntax and is not offered. **[Inference]**
  - English stemming only (`to_tsvector('english', ...)`); non-English content matches poorly. **[Inference]**
  - Ranking is plain `ts_rank`; no pagination beyond `--limit`.
  - The CLI output is not labelled as untrusted data; labelling is part of the M5 tool output.
  - The authorization owner is the OS user who owns the config file; MCP clients will need their own principals (below).
- **Decisions needed from Rio at M5.**
  1. How an AI client authenticates as itself: today `authorize` denies every principal except the owner, so an MCP server must act as the owner with the client recorded as the agent, or get its own allowed principals.
  2. Whether `sensitive` objects may be returned to an AI client at all (M4 does not gate on sensitivity).
  3. Whether denied attempts from a client can grow the ledger without bound (queries are capped at 500 characters and 50 ids per event, but not rate-limited).
- **Verified.** All 178 tests (M1 to M4) pass on a local PostgreSQL 18.7 source build, plus Ruff, mypy `--strict`, pip-audit and gitleaks. Nine deliberate weakenings (no approved filter, no expiry filter, history including proposed, no owner check, no commit on denial, no seatbelt on queries, no length limit, no guard tightening, no output sanitizer) each made tests fail, then were reverted. One of them initially escaped (see above) and led to a new test.
