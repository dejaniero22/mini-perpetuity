# Learning Note: M7 (backups and doctor)

- **A backup you cannot open is worse than none.** So the design starts from recovery: the file is a standard age file, tested with the reference `age` tool, and `mp verify-backup` proves a file opens before you need it. The weekly restore drill in the checklist is the real proof.
- **Public key in the config, secret key elsewhere.** Backups are encrypted to a public key, so the machine that makes them cannot read them. The cost is that losing the key means losing the backups. `backup-setup` refuses a key inside the backup folder and never prints the secret.
- **No plaintext on disk, no password on a command line.** The dump goes from `pg_dump`'s stdout into memory, is encrypted, and is written to a temporary name then linked into place (`os.link` never replaces an existing file; plain rename would). The password goes in a private temporary `pgpass` file that is deleted afterwards; a test spies on the real subprocess call and checks the argument list and environment.
- **`pg_dump -f -` is not stdout.** It created a file named `-` and the dump came out empty. The test that opened the backup caught it. Default output is stdout.
- **The tests found two real gaps.** (1) The everyday role could not run `pg_dump`: it reads every sequence, and the role had no `SELECT` on them. (2) A restore failed because `pg_restore` runs with an empty `search_path`, so the ledger's `CHECK (instance = instance_name())` could not find its table. Migration 0008 fixes both; neither widens what the role can change. The second is also standard function hardening.
- **Restore rules come from the data.** Ledger rows carry the instance name and a check compares it with the database, so a backup restores only into the same name. That also stops a work backup landing in the personal instance by accident. Restore is one transaction, so a failure leaves an empty instance, not half a ledger.
- **Doctor returns data.** `run_doctor()` returns checks with a status and a fix; the CLI prints them, and the web UI can render the same list. Warnings (no backup yet, stale backup, no approver) do not fail the exit code; failures (database down, migration missing, dump tool too old) do.
- **Mutations.** Twelve deliberate weakenings (plaintext, overwrite, world-readable passfile, no version check, restore into data, non-atomic restore, key inside backup folder, loose folder mode, no staleness, doctor ignoring failures, missing sequence grant, unpinned search path) were each caught. One survived at first (the folder permission set by `backup-setup`); a test now covers it.
- **Verified.** 355 tests pass on PostgreSQL 18.7 (330 earlier plus 25 new), with Ruff, mypy `--strict`, pip-audit and gitleaks.
- **Not verified.** Everything ran on Linux with PostgreSQL 18.7. The macOS steps, the first real CI run of the new apt step, and a restore on your Mac are open (MB22, MB23).
